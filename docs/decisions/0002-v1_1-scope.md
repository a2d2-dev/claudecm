# ADR-0002: v1.1 Scope Lock

- **Status:** Accepted
- **Date:** 2026-07-07
- **Owner:** CEO (LF)
- **Authority:** This memo is the single source of truth for v1.1 scope. Where it conflicts with `docs/decisions/0001-direction-lock.md`, `docs/prd/prd-v1.md`, `docs/architecture.md`, or v1 planning docs, this memo wins for v1.1 only. ADR-0001 remains the authority for v1.0.

## Context

v1.0 locked claudecm to a narrow local-first CLI: Claude Code + Codex CLI, direct write activation, explainable state, and no cloud, GUI, MCP, encryption claim, or third-tool expansion. That discipline remains correct. The next release should improve the same switching loop rather than broaden the product into adjacent management domains.

The CEO has selected the v1.1 scope after reviewing the same product benchmarks that shaped ADR-0001: `kubecm` validates the durable add/list/current/switch context-management loop, while `cc-switch` validates narrow local-first switching copy and adoption. v1.1 therefore adds convenience where that loop is still too manual, adds a terminal-native selector for the common "switch by sight" workflow, and formalizes distribution so v1.0 and later releases can be installed through normal package-manager paths.

## Decision Summary

v1.1 consists of exactly three epics:

1. **E10 - Provider preset templates.** `claudecm add --preset <name>` ships built-in transparent presets for Anthropic-compatible providers, with `moonshot`, `deepseek`, `glm`, and `qwen` as the minimum set. Presets pre-fill base URL, model, and provider fields; users still supply secrets. Generated fields are shown before save and remain overridable. Docs must state presets are convenience templates, not official-provider support or endorsement.
2. **E11 - Interactive fuzzy switch.** Bare `claudecm switch` in an interactive TTY opens a fuzzy-finder profile selector in the `kubecm` style, including active marker and preview. `claudecm switch <name> --yes` remains script-stable and non-interactive. Non-TTY behavior is unchanged.
3. **E12 - Release and distribution.** Add the release-engineering plan for GoReleaser config, GitHub release workflow, version injection via ldflags, tag `v1.0.0`, then Homebrew tap and Scoop manifest. The actual `v1.0.0` tag is handled by a separate release-engineering effort; v1.1 planning still documents the full distribution path.

## Amendments to Prior Scope

1. **PRD §5 "GUI / TUI - out. CLI only" is amended for v1.1.** E11 permits one optional terminal-only fuzzy selector behind bare `claudecm switch` when stdin/stdout are interactive TTYs. This is not a GUI, not a long-running dashboard, and not a general TUI surface. All named-argument, `--yes`, and non-TTY switch behavior remains CLI-stable.
2. **PRD §4.7 Codex custom-provider policy is amended for v1.1 presets.** v1.0 treated custom provider names as non-owned and dynamic provider ownership as post-v1. E10 permits a closed, built-in preset catalog to materialize explicit provider fields for named presets only. This does not create wildcard ownership of arbitrary provider names.
3. **ADR-0001 Decision 8 remains in force except for the E11 terminal selector carve-out.** No cloud, GUI, MCP, Skills, proxy/failover/load-balancing, IDE plugin, enterprise, or audit/cost-dashboard work is admitted by v1.1.
4. **ADR-0001 Decision 1 remains in force.** Provider presets are provider configuration templates for existing Claude Code and Codex CLI workflows. They are not support for new AI coding tools. Gemini CLI remains deferred.

## Locked Decisions

1. **Presets are transparent templates.** A preset is a local data template that expands into normal profile fields and supported tool overlays. The user sees the generated base URL, model, and provider values before saving and can override them. Presets never imply official vendor support, certification, or compatibility guarantees.
2. **Secrets are never embedded in presets.** Presets may name expected secret fields, but users supply the actual secret values through the same redaction, validation, storage, and `--dry-run` policies as `add`.
3. **No write-path bypass.** Any tool-config mutation triggered after creating or activating a preset-backed profile still routes through the existing commit/writepath invariants. E10 does not create a side path that writes Claude Code or Codex files directly.
4. **Interactive switch is an optional terminal UX.** The fuzzy selector is available only for bare `switch` in an interactive TTY. It must fall back cleanly when terminal capabilities are unavailable and must not change non-TTY exits, prompts, or script semantics.
5. **Release work is planned, not implemented here.** E12 stories describe the distribution plan. This ADR does not authorize modifying CI, GoReleaser config, package manifests, or tags as part of planning-only work.

## Explicit Deferrals

- `claudecm doctor` is deferred as a v1.2 candidate.
- Profile copy/merge is deferred; copy comes before merge when revisited.
- Shell prompt integration is deferred.
- Gemini CLI adapter is deferred.

## Rationale

Provider presets reduce setup friction without changing claudecm's core model: profiles remain explicit, local, inspectable YAML and the user still owns the secret. This matches the `cc-switch` lesson that narrow, useful switching tools win by making the common path concrete rather than by claiming broad official integrations.

The fuzzy selector brings the `kubecm` context-switching feel to the most common interactive action: "show me the profiles and let me pick one." Keeping `switch <name> --yes` and non-TTY behavior unchanged preserves the scripting contract that v1 established.

Release and distribution work must come before v1.1 feature implementation because users need a reliable v1.0 install and upgrade path before new features can be evaluated. Documenting the full path in E12 keeps the release-engineering effort aligned while leaving the actual `v1.0.0` tag to the separate release effort.

## Risks

- **R1.** Provider endpoints and model names may drift. Mitigation: presets are documented as convenience templates, kept in a visible catalog, and always overridable.
- **R2.** Users may mistake presets for official support. Mitigation: CLI and docs must avoid endorsement wording and state the no-official-support boundary.
- **R3.** Fuzzy switch could accidentally perturb scripts. Mitigation: the selector is gated on bare `switch` plus interactive TTY detection; named and non-TTY forms stay unchanged.
- **R4.** Distribution work can sprawl into package-manager support obligations. Mitigation: E12 scopes v1.0.0 release artifacts, Homebrew tap, and Scoop manifest only; broader package managers remain outside v1.1.

## Supersedes

For v1.1 only, this ADR supersedes: the PRD §5 blanket TUI exclusion as applied to the single `switch` fuzzy selector; the PRD §4.7 statement that all custom provider-name ownership is post-v1 as applied to the closed built-in preset catalog; and any planning text that treats `doctor`, copy/merge, shell prompt integration, or Gemini CLI as v1.1 work.
