# E13-S3 — `add --from-file`

**User story.**
As a user with a provider's credentials sitting in a `.env`, a shell `export` snippet, or a JSON/YAML/TOML config, I want `claudecm add <name> --from-file <path>` to parse that file into a profile draft, so onboarding is one command instead of hand-copying fields.

**Acceptance criteria.**
- `add <name> --from-file <path>` auto-detects the format by content/extension: dotenv, shell `export` lines, JSON, YAML, TOML.
- Recognized field vocabulary maps to profile core fields (base_url, api_key/auth_token, model, small_fast_model, provider where present).
- Explicit flags override values parsed from the file.
- Unreadable file, or a file whose content matches no recognized format / yields no usable fields, is refused with a clear message; no partial profile is written (NFR-S1).
- File is read read-only; nothing outside `add`'s normal write to `~/.claudecm/profiles/<name>.yaml` is touched. Zero network. Reuses `add` `--dry-run`/redaction/validation/overwrite/save; no auto-activation.

**PRD/architecture refs.** ADR-0003 Decision Summary item 2, Locked Decision 6; PRD FR-1, NFR-S1, NFR-S8; Architecture §2.1.

**Test plan.**
- Happy: a `.env` with `ANTHROPIC_BASE_URL=` + `ANTHROPIC_AUTH_TOKEN=` → draft populated; dry-run redacts key.
- Happy: a JSON `{ "base_url": ..., "api_key": ..., "model": ... }` → draft populated.
- Edge: a shell `export ANTHROPIC_MODEL=...` snippet → model parsed.
- Edge: nonexistent path → refused "cannot read file"; a binary/garbage file → refused "unrecognized config format".

**No fallback writes.** Unrecognized/unreadable input refuses; never emit a half-populated profile.

**Complexity.** M.

**Dependencies.** E6-S3, E1-S1.
