# E11-S2 — Fuzzy profile selector with active marker

**User story.**
As a claudecm user, I want bare `switch` to show a fuzzy-searchable profile list with the active profile clearly marked, so I can choose the target profile quickly without typing the exact name.

**Acceptance criteria.**
- The selector lists all valid profiles that `list` would show, using the same profile-store read and corruption handling.
- The currently active profile is marked visibly and sorted consistently with the base list ordering before filtering.
- Fuzzy filtering matches profile names and useful non-secret context such as notes/provider/model where available.
- Empty profile store, corrupt profile store, or invalid active pointer produce clear errors and no selector mutation.
- Selecting the already-active profile exits cleanly after showing that no switch is needed, with no tool-file write.
- The selector remains terminal-only and does not introduce a GUI, background service, or persistent state.

**PRD/architecture refs.** ADR-0002 E11; PRD FR-3, FR-4, NFR-S4, NFR-S8; Architecture §7.

**Test plan.**
- Happy: three profiles with one active → selector displays all three, active marker appears, fuzzy query narrows results.
- Edge: no profiles → clear error; active profile missing → existing store-integrity error; selecting active profile produces no write.

**No fallback writes.** Read/list/selection only; no direct writes from selector UI.

**Complexity.** M.

**Dependencies.** E11-S1, E6-S1, E6-S10.
