# E13-S4 — `add --from-text` (local heuristic paste)

**User story.**
As a user who just copied a messy blob (provider docs, a chat message, a half-formatted snippet), I want `claudecm add <name> --from-text "<blob>"` (or `--from-text -` to read stdin) to locally extract the fields into a profile draft, so I can onboard without hand-parsing and without anything leaving my machine.

**Acceptance criteria.**
- `add <name> --from-text <text>` and `add <name> --from-text -` (stdin) run the `internal/blobparse` (E13-S1) local extractor and populate the profile draft from the extracted fields.
- Zero network on this path; it is the local-heuristic default of the paste flow.
- Explicit flags override extracted values.
- When the extractor finds no API key/token, the command refuses with a clear message (NFR-S1) unless a key is supplied by flag; no keyless profile is written.
- Reuses `add` `--dry-run`/redaction/validation/overwrite/save; secrets redacted in preview; no auto-activation.

**PRD/architecture refs.** ADR-0003 Decision Summary item 3, Locked Decisions 1, 2, 6; PRD FR-1, NFR-S1, NFR-S8.

**Test plan.**
- Happy: `--from-text "export ANTHROPIC_BASE_URL=... ANTHROPIC_AUTH_TOKEN=sk-..."` → draft populated; dry-run redacts key.
- Happy: `--from-text -` reading a prose blob from stdin → fields extracted.
- Edge: blob with base_url + model but no key → refused unless `--api-key` supplied.
- Edge: blob with nothing recognizable → refused "could not extract profile fields from text".

**No fallback writes.** No keyless/partial profile is written; refuse when the key is absent and unsupplied.

**Complexity.** M.

**Dependencies.** E13-S1, E6-S3.
