# E11-S4 — Selector handoff to existing switch pipeline

**User story.**
As a claudecm maintainer, I want the fuzzy selector to hand the selected profile name to the existing switch pipeline, so interactive selection has the same safety, diff, backup, and rollback semantics as `switch <name>`.

**Acceptance criteria.**
- After selection, the command invokes the same switch execution path used by named `switch`, passing only the selected profile name and existing flags.
- The explain-style pre-apply diff is shown after selection and before any write.
- Existing confirmation rules apply unchanged: `--yes`, `--strict`, non-owned-change prompts, and `--dry-run` behave the same as named switch.
- Successful switch reports the new active profile and backup paths exactly like named switch.
- Failures from writepath/commit, including malformed config, concurrent edit, and partial failure, surface through the same error handling as named switch.
- Selector tests assert that no code path sequences multiple `writepath.Apply` calls directly.

**PRD/architecture refs.** ADR-0002 Locked Decision 4; PRD FR-4, FR-5, FR-15, FR-16, NFR-S1, NFR-C2; Architecture §4, §5, §7.

**Test plan.**
- Happy: select `relay-a` → same diff/write/report output as `switch relay-a`.
- Edge: select profile then target config is malformed → NFR-S1 refusal; `--dry-run` after selection prints diff only; concurrent edit returns exit code 2.

**No fallback writes.** Selector handoff must use the named switch pipeline and `commit`; no direct tool-file writes.

**Complexity.** M.

**Dependencies.** E11-S1, E11-S2, E11-S3, E6-S2, E7-S1..E7-S5.
