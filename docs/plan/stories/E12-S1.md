# E12-S1 — Version metadata and ldflags contract

**User story.**
As a claudecm user, I want `claudecm version` builds to report release version, commit, and build date from ldflags, so installed binaries are traceable to a GitHub release artifact.

**Acceptance criteria.**
- The release plan defines ldflags for `version`, `commit`, `date`, and optional dirty/build metadata, matching the existing `cmd/version` / `pkg/version` contract.
- Local snapshot builds have deterministic fallback values that make non-release binaries obvious.
- Release builds populate version metadata from the Git tag and GitHub Actions context.
- `claudecm version` output is documented as the smoke-test command for package-manager installs.
- The plan includes validation for clean tree, semver tag format, and expected module path `github.com/a2d2-dev/claudecm`.
- No telemetry, update-checking, or network call is added to `version`.

**PRD/architecture refs.** ADR-0002 E12, Locked Decision 5; E6-S9; Architecture source-tree release notes.

**Test plan.**
- Happy: build with ldflags `v1.0.0`, commit, date → `claudecm version` prints those values.
- Edge: snapshot build without ldflags prints obvious dev values; malformed tag is refused by release validation.

**No fallback writes.** N/A — build metadata only.

**Complexity.** S.

**Dependencies.** E6-S9.
