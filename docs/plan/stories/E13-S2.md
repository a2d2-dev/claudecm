# E13-S2 — `add --from-env`

**User story.**
As a user who already has `ANTHROPIC_*` (or Codex) variables exported in my shell, I want `claudecm add <name> --from-env` to read them and build a profile draft, so I don't retype values that are already in my environment.

**Acceptance criteria.**
- `add <name> --from-env` reads the Claude Code / Codex environment-variable allowlist (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, and the Codex equivalents) and populates the corresponding profile core fields.
- Env reads route through `internal/envextract` (not ad-hoc `os.Getenv` scattered in `cmd/`).
- Explicit flags win over env: e.g. `--model` overrides `ANTHROPIC_MODEL` from the environment.
- If no API key/token is present in the environment, the command refuses with a clear message rather than writing a keyless profile (NFR-S1, no fallback).
- Reuses the existing `add` pipeline: `--dry-run`, redaction, name validation, overwrite guard, `SaveProfile`; does not auto-activate. Zero network.

**PRD/architecture refs.** ADR-0003 Decision Summary item 1; ADR-0001 Decision 4 (secondary env flow); PRD FR-1, NFR-E1, NFR-S1; Architecture §2.1.

**Test plan.**
- Happy: env has base_url + auth token + model → draft populated; `--dry-run` shows redacted key.
- Edge: env has base_url + model but no key → refused with "no API key found in environment".
- Edge: `--from-env` plus explicit `--model foo` → `foo` wins over env model.

**No fallback writes.** No keyless/partial profile is written; refuse when required fields are absent.

**Complexity.** S.

**Dependencies.** E6-S3, E5-S1 (envextract allowlist).
