# E12-S5 — Scoop manifest distribution plan

**User story.**
As a Windows user, I want claudecm installable through Scoop after v1.0.0 ships, so I can install and upgrade it through a familiar package-manager workflow.

**Acceptance criteria.**
- The plan identifies the Scoop bucket, manifest name, architecture-specific artifact URLs, checksums, binary path, license, homepage, and version metadata.
- Manifest updates consume GitHub Release artifacts and checksums produced by E12-S3.
- Install smoke includes `scoop install`, `claudecm version`, and `claudecm --help`.
- Upgrade smoke covers `scoop update claudecm` from a prior version when available.
- Rollback guidance covers reverting a bad manifest update and communicating the known-good version.
- The manifest does not add telemetry, services, shell prompt integration, cloud behavior, or Windows credential-store claims.

**PRD/architecture refs.** ADR-0002 E12; E12-S2; E12-S3.

**Test plan.**
- Happy: manifest installs release artifact, checksum matches, `claudecm version` reports the tag.
- Edge: checksum mismatch blocks install; missing Windows artifact blocks manifest update before merge.

**No fallback writes.** N/A for planning; package installation writes are Scoop-managed, not claudecm tool-config writes.

**Complexity.** M.

**Dependencies.** E12-S2, E12-S3.
