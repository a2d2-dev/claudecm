# E11-S3 — Selector preview with redacted effective context

**User story.**
As a claudecm user, I want the fuzzy selector to preview each highlighted profile's effective context with secrets redacted, so I can distinguish similar profiles before switching.

**Acceptance criteria.**
- Highlighting a profile shows a preview containing profile name, provider/base URL/model context per supported tool where available, notes, and active/current marker.
- Preview values reuse resolver/explain formatting where practical and follow default secret-redaction policy.
- `--reveal`, if globally enabled and allowed by existing policy, is the only path that can reveal secret fields; otherwise secrets remain redacted.
- Preview generation does not read project-scope Claude Code files and does not contact remote providers.
- Preview errors for one profile are displayed as scoped preview errors without crashing the whole selector when other profiles remain valid.
- Preview layout is usable in narrow terminals: text truncates or wraps predictably without overlapping rows or controls.

**PRD/architecture refs.** ADR-0002 E11; PRD FR-6, FR-7, NFR-S8, §5; Architecture §6, §7.

**Test plan.**
- Happy: highlighting `relay-a` shows redacted base URL/model/tool context and notes.
- Edge: profile with invalid optional field shows a preview-scoped error; narrow terminal snapshot has no overlapping text; secrets remain redacted.

**No fallback writes.** Preview is read-only and never mutates profile store or tool files.

**Complexity.** M.

**Dependencies.** E11-S2, E5-S5, E6-S1.
