# E13-S5 — `add --ai` (opt-in, secret-free LLM-assisted parse)

**User story.**
As a user whose pasted blob is too messy for the local heuristic, I want `claudecm add <name> --from-text <blob> --ai` to strip my secrets locally, send only the desensitized text to an LLM using my own already-configured credentials, get back a structured profile, and re-inject the secret locally — so I get smart parsing without any secret ever leaving my machine.

**Acceptance criteria.**
- `--ai` is off by default and must be passed explicitly per invocation; there is no persisted "always AI" mode.
- The path runs `internal/blobparse` (E13-S1) first, holds captured secrets in-process, and constructs an outbound request containing **only** the desensitized text — asserted by test to contain no secret-shaped token.
- Credentials for the parse call default to the currently-active claudecm profile's `base_url`/`api_key`; `--ai-profile <name>` overrides which profile lends credentials. The borrowed credential is never logged or persisted.
- The LLM is asked to return a structured profile (JSON conforming to the core-field schema). Non-conforming output is refused (NFR-S1); no guessed/half profile is written.
- After a conforming response, the held secret is re-injected locally into the draft, then the normal `add` preview/validation/overwrite/save runs; secrets redacted in preview; no auto-activation.
- Interactive runs name the credential-lending profile and display the exact desensitized payload before sending; non-interactive runs proceed only with `--ai` explicitly set.
- No remote provider probe/validation of the resulting key or model.

**PRD/architecture refs.** ADR-0003 Amendments 1-2, Locked Decisions 1-4; PRD FR-1, NFR-S1, NFR-S8; ADR-0001 Decision 8 (as amended by ADR-0003 for this path only).

**Test plan.**
- Happy (mocked LLM): desensitized blob → mock returns conforming JSON → draft built, secret re-injected locally, dry-run redacts key.
- Security: assert the outbound request body contains no secret-shaped token from the input (redaction gate).
- Edge: mock returns malformed/non-conforming output → refused, nothing written.
- Edge: no active profile and no `--ai-profile` → refused "no credentials available for --ai parse".
- Edge: `--ai-profile missing` → refused with unknown-profile error.

**No fallback writes.** Non-conforming LLM output or missing credentials refuse; never write a guessed profile.

**Complexity.** L.

**Dependencies.** E13-S1, E13-S4, E6-S3, E5 (resolver/active-profile lookup).
