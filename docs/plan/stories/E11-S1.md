# E11-S1 — Interactive TTY detection and `switch` dispatch

**User story.**
As a shell user, I want bare `claudecm switch` to open an interactive selector only when I am in a real terminal, so scripts and CI keep the same behavior they had in v1.

**Acceptance criteria.**
- Bare `claudecm switch` dispatches to the fuzzy selector only when no profile name is provided and stdin/stdout are interactive TTYs.
- Bare `switch` in non-TTY contexts preserves the v1 behavior and exit code; it never opens, blocks on, or waits for an interactive selector.
- `claudecm switch <name>` and `claudecm switch <name> --yes` bypass the selector entirely.
- Existing confirmation behavior for named switch, `--dry-run`, `--yes`, and `--strict` is unchanged.
- Terminal detection is isolated behind a small interface so tests can cover TTY and non-TTY branches deterministically.
- Cancellation before a profile is selected exits without changing active profile state or touching tool files.

**PRD/architecture refs.** ADR-0002 Amendments 1, Locked Decision 4; PRD FR-4, FR-15; Architecture §7.

**Test plan.**
- Happy: fake TTY + bare `switch` invokes selector path; `switch official --yes` invokes named path.
- Edge: fake non-TTY + bare `switch` returns the existing v1 error/usage path; selector cancellation has no writes.

**No fallback writes.** Dispatch and cancellation do not mutate profile store or tool files.

**Complexity.** S.

**Dependencies.** E6-S2.
