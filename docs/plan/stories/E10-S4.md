# E10-S4 — Preset docs, help text, and no-official-support boundary

**User story.**
As a claudecm user, I want preset documentation and command help to clearly explain what presets generate and what they do not guarantee, so I do not confuse convenience templates with official provider support.

**Acceptance criteria.**
- `claudecm add --help` documents `--preset <name>`, lists or points to available presets, and states that presets are convenience templates.
- README/quickstart docs show one preset example with generated fields visible and secrets supplied by the user.
- Docs explicitly state that built-in presets are not official support, certification, endorsement, or compatibility guarantees from any provider.
- Docs explain that preset fields are overridable and that endpoint/model drift may require user edits.
- Docs do not imply support for new AI coding tools, provider proxying, failover, cloud sync, MCP, GUI, or encryption.
- Preset docs preserve default secret-redaction wording and do not print example real secrets.

**PRD/architecture refs.** ADR-0002 Locked Decisions 1-2, Risks R1-R2; PRD NFR-D1, §5; E9 docs voice.

**Test plan.**
- Happy: help and docs include `moonshot`, `deepseek`, `glm`, `qwen` and show a redacted preset add example.
- Edge: documentation grep finds no official-support/endorsement wording and no out-of-scope feature claims.

**No fallback writes.** N/A — docs/help only.

**Complexity.** S.

**Dependencies.** E10-S1, E10-S2, E9-S1.
