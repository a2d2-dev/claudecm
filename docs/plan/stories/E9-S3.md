# E9-S3 — `explain` + `switch --dry-run` asciinema demo

**User story.**
As a prospective claudecm user reading the README, I want a 60-second asciinema cast showing `explain` resolving an effective config and `switch --dry-run` printing the pre-apply diff, so I trust the tool before installing it.

**Acceptance criteria.**
- Two asciinema casts (or one combined cast) are recorded and embedded in the README.
- The cast uses a sandboxed `--home /tmp/claudecm-demo` so no real credentials are exposed.
- Default redaction (`sk-***last4`) is visible in the cast.
- The cast is regeneratable from a script committed alongside the asciinema file under `docs/demo/`.

**PRD/architecture refs.** PRD FR-4, FR-7, NFR-S8; Architecture §7.

**Test plan.**
- Happy: cast renders in GitHub README; redaction visible.
- Edge: any cast revealing a plaintext key triggers the CI grep guard (E8-S6) for `sk-` patterns.

**No fallback writes.** N/A — docs.

**Complexity.** S.

**Dependencies.** E5-S5, E6-S2.

**Implementation note (2026-07-02).**

The v1 docs-polish PR (E9) split this story into two deliverables:

1. **Committed in-PR.** `docs/demo/record.sh` — an idempotent, sandboxed
   regeneration script that seeds `/tmp/claudecm-demo` with synthetic
   credentials, imports Claude Code + Codex, adds a `work` profile, then
   records `explain` + `switch --dry-run` to `docs/demo/claudecm-demo.cast`
   via `asciinema rec`. `docs/demo/README.md` documents the workflow and
   the exact steps the cast must show.
2. **Deferred to a maintainer.** The actual `.cast` output. Recording
   asciinema requires an interactive TTY and the `asciinema` binary on
   the host; the implementation environment for this PR was headless and
   did not have both. The cast file will be produced by running
   `bash docs/demo/record.sh` on a maintainer's workstation and committed
   in a follow-up docs PR. All ACs about the cast's contents (sandboxed
   `--home`, default `sk-***last4` redaction visible, script-regeneratable)
   are pinned by the committed script; landing the `.cast` file is the
   only remaining task.

Rationale: shipping the script now unblocks the E9 close on v1 while
guaranteeing the cast, when produced, is byte-for-byte reproducible and
covered by the E8-S6 CI grep guard for both cryptographic claims and any
`sk-` string that escapes redaction.
