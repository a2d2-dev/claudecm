# E10-S1 — Built-in provider preset catalog

**User story.**
As a claudecm user, I want a built-in catalog of transparent Anthropic-compatible provider presets, so I can start from a known base URL/model/provider template without hunting for every field.

**Acceptance criteria.**
- A closed built-in preset catalog is declared in code with at least `moonshot`, `deepseek`, `glm`, and `qwen`.
- Each preset includes a stable preset name, display name, provider key, base URL, default model, supported tool overlays, expected secret fields, and a short no-official-support disclaimer string.
- Preset entries expand only into the existing unified profile shape (`schema_version: 1`, core fields, sparse `tools` overlays); no preset-specific profile schema is introduced.
- Preset catalog lookup is case-insensitive for user input but stores canonical lowercase preset names in metadata/output.
- Unknown preset names are refused with a clear message listing available presets.
- Presets are data templates only; they do not probe remote provider endpoints or validate credentials online.

**PRD/architecture refs.** ADR-0002 Decision Summary/E10, Locked Decisions 1-3; PRD FR-1, NFR-M1; Architecture §2.1.

**Test plan.**
- Happy: lookup `moonshot`, `deepseek`, `glm`, `qwen` → each expands to a valid profile draft with expected non-secret fields.
- Edge: lookup `MoonShot` canonicalizes; lookup `unknown` fails with available preset names; catalog contains no secret values.

**No fallback writes.** N/A — catalog declaration only.

**Complexity.** S.

**Dependencies.** E1-S1, E6-S3.
