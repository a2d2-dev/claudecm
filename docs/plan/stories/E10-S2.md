# E10-S2 — `cmd/add --preset` profile draft expansion

**User story.**
As a claudecm user, I want `claudecm add --preset <name>` to pre-fill provider fields from the preset catalog while letting me supply the secret and override generated fields before the profile is saved.

**Acceptance criteria.**
- `claudecm add --preset <name>` resolves the built-in preset and creates the same profile draft path as `add` with explicit flags.
- The command requires or prompts for the profile name and required secret values using existing `add` validation and redaction behavior.
- Generated fields (`base_url`, `model`, provider/tool overlay fields) are shown before save in interactive mode and in `--dry-run` output.
- Explicit flags and `--set` values override preset-generated fields, with the final merged draft shown before save.
- `--dry-run` prints the would-be profile with secrets redacted by default and performs no writes.
- Existing name, invalid name, missing required secret in non-interactive mode, or invalid override values are refused without writing.

**PRD/architecture refs.** ADR-0002 E10, Locked Decisions 1-3; PRD FR-1, FR-15, NFR-S5, NFR-S8, NFR-M1; Architecture §7.

**Test plan.**
- Happy: `claudecm add work --preset moonshot --api-key sk-test --dry-run` prints a valid redacted profile draft with preset fields.
- Edge: non-interactive preset add without a required secret fails; explicit `--model` overrides the preset model; existing profile name refuses without overwrite.

**No fallback writes.** Invalid preset/name/secret/override → refuse, no profile write.

**Complexity.** M.

**Dependencies.** E10-S1, E6-S3.
